2 · Supporting information (SI)

Recipes, suppliers and extra tables are often only in the SI. It is settled before the paper is read, so the extraction reads the paper and its SI together, once. The first check reads the paper's text with rules and costs nothing; press "Look for the paper's SI from the journal website" to let a model read it instead (under a cent with Haiku), which also pulls out the SI address when the paper prints one.

3 · Extract

A Big model maps the devices first. The extract model fills the sheets, and a small model decides accept / verify_more / revise per row.

Output: one .xlsx per device in the Raw Data layout, plus review.csv. A number the model read off a plot is an estimate: its row (human_read) says which figure and what the graph shows, and you read the plot again. Check every verify_more row before moving the files into Raw Data.

Columns of the processed tables

Download CSV Download Markdown

The goal of the research is to find insights from the extracted papers (which class of substance changes the device results, how and through which channel), not to tune a PCE or a retention value. Each column is rated by how much that analysis needs it, so the dataset can be cut down to what matters.

  • core: the analysis reads it: what was changed, what happened, through which mechanism.
  • context: needed to compare fairly (control, perovskite composition, measurement condition).
  • provenance: identifiers and source traces; kept for joins and audit, not analysed.
  • drop: redundant, constant, empty or a raw leftover: a candidate to remove.
